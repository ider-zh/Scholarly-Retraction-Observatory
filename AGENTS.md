# Website report design

For website report UI work, read and use both project-local skills:

- `.agents/skills/frontend-design/SKILL.md` for visual direction, typography, layout and interaction design.
- `.agents/skills/research-report-design/SKILL.md` for research narrative, statistical integrity, evidence binding and browser acceptance.

Use `frontend-design` as the primary visual-design skill, rather than combining competing visual-direction skills. Follow the user's current brief, `DESIGN.md`, `docs/WEBSITE_REPORT_DESIGN.md` and the statistical specifications over generic aesthetic suggestions. Keep the report research-first, Chinese-readable and restrained; retain the persistent chapter directory and existing React/chart capabilities unless the user requests a change.

Do not change published aggregates, denominators, source rules or analysis methods for visual consistency. Preserve sources/slice/deep-link behavior, data validation, exports and accessible tables. Check actual browser rendering at desktop, tablet and mobile sizes when changing the UI; report limitations honestly.

Installing a skill does not itself redesign the site. Do not claim visual changes or validation that were not performed. Do not commit, push or deploy without user authorization.
