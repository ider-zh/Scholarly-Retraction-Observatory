# 性能基准

合成内核基准已提供可重复执行脚本，实际结果见 `ENGINE_RESULTS.md`。
它不代替真实快照的分层基准，也不意味着生产图统计已经验收。
分层覆盖无参考、低/高参考数、低/高被引、极高入度共享参考、不同年代及 core/xpac。
测试样本的计算仍需完整提取所选 focal 所需邻域；任意裁剪引用图不能冒充真实 NR。

记录样本定义、快照/代码/配置哈希、邻域规模、精确参考结果、运行时间、总 RAM 峰值、
I/O、索引/结果/spill 字节数、异常与恢复结果。对高连接尾部单独估算，
不得只用平均论文耗时线性外推全图并承诺完成时间。

遵守 SPEC 的 40 CPU / 384 GiB 总 RAM / 新增 4 TB 且保留 1 TB 空间限制。
大型基准产物保存在 `/mnt/hg02` 的外部版本目录；这里只提交小型汇总和方法说明。

## Go / Rust 并发读图合成基准

```bash
python disruption/benchmarks/run_engine.py \
  --output /mnt/hg02/openalex-snapshot/analysis/disruption/benchmarks/engine-20260923
```

需要现有 Go、Rust、Python 及 GNU `/usr/bin/time`，不下载安装依赖。
图构建后只读共享，使用紧凑出边／入边 CSR；工作线程独享节点访问戳和分类位图。
按相同确定性生成规则构建 120,000 个节点、1,855,547 条去重边，
每个非首年节点最多 16 个严格早年的参考文献，其中一个指向 1,024 个共享参考节点之一。
24,000 个固定 focal 查询各重复 100 次，避免亚毫秒任务掩盖并行效果；
这是热缓存吞吐测试，重复查询不等于 240 万篇不同论文。

每次查询计算发表后第 1…5 个自然年的 NF/NB/NR，按未来 Work 去重，
不按共享参考数计数。独立 Python 集合实现计算全部 24,000 个 focal 的校验和，
Go/Rust 在 1、8、40 个 worker 下各运行至少 3 次，交替语言顺序，核对每次结果。
仅比较计算阶段的墙钟中位数；构图时间单独记录，Go/Rust 构图去重容器不同，
因此不据此比较构图语言性能。RSS 是整个子进程的 GNU time 峰值，并非只读图大小。
Go 使用默认优化构建，Rust 使用 `rustc -O`，均未指定机器特化优化。

本基准不涵盖磁盘 I/O、压缩、真实高入度尾部、缺失年份、全部年龄桶、
两个窗口政策和图闭合审计；不能据此线性外推全图耗时或证明 40 线程总是最优。
生产实现必须另外满足 `../ACCEPTANCE.md`，真实快照分层成本评估仍然必要。
